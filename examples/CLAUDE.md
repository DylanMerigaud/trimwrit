# House rules

This file is the demonstration target for trimwrit. Everything below the heading was written by
`trimwrit integrate`, never by hand, and every block names the case that keeps it alive.

Delete any of them and `trimwrit run` will tell you whether it mattered.


<!-- trimwrit: R0002 case 0002, 2026-08-23: a launch post went out with three em-dashes and read as machine written to the audience it was aimed at -->
Never use an em-dash or an en-dash, anywhere: prose, commit messages, code comments, file names. Use a comma, a colon, parentheses, or start a new sentence. The ASCII hyphen is fine.


<!-- trimwrit: R0003 case 0003, 2026-08-23: an estimate in hours was quoted back inside a client thread and was wrong by 3x -->
Never put a time estimate on work. No hours, no days, no weeks, no sprint counts, no 'quick' or 'should be fast'. Describe what the work involves and what it depends on, and stop there.


<!-- trimwrit: R0005 case 0005, 2026-08-23: a long answer buried its recommendation in the middle and the reader stopped before reaching it -->
End every answer with a short closing block, a few lines at most, and put nothing else in it: the options, what each one costs, and which one you recommend, marked as the recommendation. A menu with no pick hands the work back to the reader. All the detail and evidence goes ABOVE that block.
